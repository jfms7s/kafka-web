# kafka-web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development for every task. Each task is developed on its own branch by one developer agent, reviewed by an adversarial reviewer, then merged `--no-ff` into `main` by the orchestrator. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local, single-user web app (FastAPI + confluent-kafka backend, React + TypeScript frontend) to browse topics, consume/stream/publish messages, and manage consumer groups on multiple Kafka clusters at once.

**Architecture:** Backend modules with one job each — `config/` (YAML store, OS keyring, truststore→PEM), `kafka/` (librdkafka config translation, per-cluster connection registry, error mapping), `services/` (plain sync Kafka operations, no FastAPI imports), `api/` (routers, pydantic models, write guard). Blocking confluent-kafka calls run in FastAPI's threadpool (`def` handlers); only the live-stream WebSocket is `async`, bridged to a consumer thread. Frontend: React Router (URL = active cluster/topic), TanStack Query, API types generated from the backend's OpenAPI schema.

**Tech Stack:** Python 3.12, uv, FastAPI, uvicorn, confluent-kafka ≥ 2.6, keyring, pyjks, cryptography, pyyaml, pydantic v2, pytest, testcontainers, ruff · Node 20.18, Vite 6, React 19, TypeScript 5, Tailwind CSS 4 (`@tailwindcss/vite`), react-router 7, @tanstack/react-query 5, @tanstack/react-virtual 3, openapi-typescript 7 + openapi-fetch, vitest 3, @testing-library/react, eslint 9.

## Review Focus

Inputs the spec implies but no feature test naturally exercises — each has a pinned test in the owning task:

1. **Unreachable or wrong brokers** (typo in bootstrap, port closed): Test connection / connect must return `504 kafka_timeout` (or `502`) within ~12 s, never hang — librdkafka retries forever unless the call has a timeout. → Task 3, `test_connect_unreachable_broker_times_out`.
2. **Empty topics / empty partitions** with `start=latest`: snapshot returns `[]` promptly, no division by zero when no partition has data. → Task 6, `test_plan_latest_all_partitions_empty` + integration `test_snapshot_empty_topic_returns_fast`.
3. **Binary / null data**: non-UTF-8 keys/values/headers, `None` key, tombstone (`None` value), JSON scalars like `"null"` or `"42"`. → Task 6, decode tests.
4. **Hand-edited or missing config**: no config dir, empty `clusters.yaml`, malformed YAML, an entry that fails validation → list returns `[]` for missing/empty; malformed → `500 config_file_invalid` naming the problem; never a stack trace. → Task 2.
5. **Browser tab closed mid-stream / cluster deleted while streaming**: the consumer thread stops and the consumer is closed within ~1 s; no thread leak. → Task 7, `test_stream_stops_on_client_disconnect` + `test_stream_stops_when_cluster_deleted`.

```python
class TruststoreError(ValidationFailed):   # always field="truststore"
    # codes: "truststore_invalid_base64", "truststore_unrecognized_format",
    #        "truststore_password_required", "truststore_invalid_password", "truststore_empty"

def truststore_to_pem(data: bytes, password: str | None) -> str
def truststore_b64_to_pem(b64: str, password: str | None) -> str   # strips whitespace, strict b64 decode
@dataclass(frozen=True)
class CertSummary:
    subject: str          # RFC 4514 string, e.g. "CN=Test CA"
    not_after: datetime   # tz-aware UTC
def summarize_pem(pem: str) -> list[CertSummary]
```

Conversion rules (port of the notebook function, made strict):
- magic `FEEDFEED` / `CECECECE` → `jks.KeyStore.loads(data, password)`; certs = `trusted cert entries` + the cert chains of private-key entries are **ignored**. `password is None` → try loading with `""` is NOT allowed; instead attempt `jks.KeyStore.loads(data, None)`-equivalent integrity-skip if pyjks supports it, otherwise raise `truststore_password_required`. Wrong password (pyjks `KeystoreSignatureException`) → `truststore_invalid_password`.
- starts with `-----BEGIN` (after lstrip) → parse every certificate with `x509.load_pem_x509_certificates`; re-serialize (normalizes); zero certs → `truststore_empty`.
- first byte `0x30` → try `pkcs12.load_pkcs12(data, pw)`; on `ValueError` mentioning password/MAC with a non-DER-cert payload → if `password is None` → `truststore_password_required` else `truststore_invalid_password`; if PKCS12 parse fails for a structural reason, try `x509.load_der_x509_certificate(data)`; if that fails → `truststore_unrecognized_format`.
- anything else → `truststore_unrecognized_format` (message includes `magic=<hex>`).
- Result with zero certificates → `truststore_empty`. Output is concatenated PEM, one cert per block, ending in `\n`.

Store rules:
- Directory created `0700`; `clusters.yaml` and every PEM written `0600` via temp file + `os.replace` (atomic). YAML shape: `{"clusters": [ ... ]}` with `exclude_none`.
- Create/update order: `materialize` (all validation + truststore conversion first, nothing written on failure) → write PEM → set keyring secret → write YAML. TLS create with no `truststore_base64` → `ValidationFailed(code="truststore_required", field="truststore")`. Update with empty `truststore_base64` keeps existing PEM; with a value replaces it. Update with empty `sasl_password` keeps the existing keyring secret. SASL create with empty password → `ValidationFailed(code="sasl_password_required", field="sasl_password")`. Switching an existing cluster from TLS → non-TLS deletes its PEM; from SASL → non-SASL deletes its keyring secret.
- PEM file name: `truststores/{name}.pem`.
- `usability`: TLS and PEM missing/unreadable/zero certs → unusable; SASL and keyring returns None → unusable; keyring unavailable on read → unusable with reason.
